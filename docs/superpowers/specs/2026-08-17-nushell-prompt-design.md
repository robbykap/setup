# Nushell inline powerline prompt

## Goal

Replace Nushell's stock prompt with a single-line powerline prompt that shows
working directory, git branch state, and the current time, colored in
Catppuccin Mocha.

```
 ~/Documents/github/setup   main ▲2 ~1   14:32:07 ❯ ls
```

Everything sits on one line; the command is typed immediately after the `❯`.
There is no header row above the input and no footer row below it.

## Scope

In scope: the prompt itself, the file that defines it, and an installer that
wires it into Nushell's config.

Out of scope: changing the ghostty theme (currently Catppuccin Frappe, while
this prompt is Mocha — a deliberate, accepted mismatch), Nushell keybindings,
completions, aliases, and any other shell configuration.

## Layout

Three flag segments, left to right, then the indicator. Each segment paints a
background color and ends with a `` separator drawn in the segment's
background color over the *next* segment's background, so the flags flow into
each other without a seam. The final separator is drawn over the terminal
default background.

| Segment | Background | Foreground | Content |
|---|---|---|---|
| path | `blue #89b4fa` | `crust #11111b` | cwd, `~`-shortened, last 3 components |
| git | `mauve #cba6f7` | `crust #11111b` | ` branch` plus `▲n` `▼n` `~n` counters |
| time | `surface1 #45475a` | `subtext0 #a6adc8` | ` HH:MM:SS` |
| indicator | none | `green #a6e3a1` / `red #f38ba8` | `❯ ` |

Colors are emitted as ANSI truecolor escapes with explicit hex values. The
palette is defined once as a record at the top of the file and referenced by
name throughout; no hex literal appears more than once.

### Path segment

The cwd with `$env.HOME` replaced by `~`. If the result has more than three
path components, keep the last three and prefix `…/`. The root directory
renders as `/`. When the shell is running as root (`id -u` is 0), the
background is `red #f38ba8` instead of blue, as a standing warning.

### Git segment

Populated from a single `git status --porcelain=2 --branch` invocation in the
current directory:

- branch name from the `# branch.head` line
- `▲n` when `# branch.ab` reports a nonzero ahead count
- `▼n` when it reports a nonzero behind count
- `~n` where n is the number of tracked-file entry lines (changed, renamed,
  or unmerged), omitted when zero

A detached HEAD renders as the short commit sha. When the directory is not a
git repository, **the entire segment is omitted** — the path flag's separator
flows directly into the time flag, leaving no empty segment and no stray
separator.

### Time segment

`HH:MM:SS` in 24-hour local time, evaluated when the prompt is rendered. It
updates on each new prompt, not continuously.

### Indicator

`❯ ` in green normally, red when `$env.LAST_EXIT_CODE` is nonzero. This is the
only place command outcome is surfaced, since there is no footer.

## Failure and degradation

The prompt must never hang or error, because a broken prompt makes the shell
unusable and is awkward to recover from.

- The git call is wrapped so any failure — git missing, repository corrupt,
  unreadable — degrades to omitting the git segment rather than propagating.
- Any unexpected error while building a segment degrades that segment away; a
  prompt with fewer flags is always preferable to a stack trace.
- The powerline glyphs `` (U+E0B0) and `` (U+E0A0) require a Nerd Font.
  Ghostty ships JetBrains Mono Nerd Font as its default and the workspace
  config does not override `font-family`, so they are expected to render. This
  is verified before the work is called done; if the glyphs do not render, the
  separator falls back to `▏` and the branch icon is dropped.

## Files

```
nushell/prompt.nu     the palette, segment builders, and PROMPT_COMMAND hooks
nushell/install.sh    idempotent installer
nushell/README.md     what it looks like, how to install, how to uninstall
```

`prompt.nu` sets `$env.PROMPT_COMMAND` to a closure returning the assembled
flags, and sets `$env.PROMPT_INDICATOR` to the `❯`. It clears
`PROMPT_COMMAND_RIGHT` so no stock right-prompt appears. Segment builders are
separate commands (`path-flag`, `git-flag`, `time-flag`) that each return a
string or nothing, so each can be tested in isolation by calling it directly.

`install.sh` follows the structure of `ghostty/install.sh`: `set -eu`,
`--dry-run` support, a `say`/`act` pair, and the same symlink refusal. It
appends a marked `source` line to
`~/Library/Application Support/nushell/config.nu`:

```
# Generated by nushell/install.sh
source "<abs path>/nushell/prompt.nu"
```

It is idempotent — re-running replaces the existing marked line rather than
appending a second one — and copies config.nu to `config.nu.bak` before
modifying it. If config.nu is a symlink, it refuses and explains, exactly as
the ghostty installer does.

## Testing

`nushell/run-tests.sh`, invoking `nu` with `prompt.nu` sourced:

- path flag shortens `$HOME` to `~`
- path flag truncates a deep path to three components with a `…/` prefix
- git flag returns the branch name inside a repo created in a temp dir
- git flag reports `~n` after a tracked file is modified
- git flag returns nothing in a non-repo temp dir
- the assembled prompt in a non-repo directory contains exactly two separators
- the indicator is red when `LAST_EXIT_CODE` is nonzero, green when zero
- `install.sh --dry-run` writes nothing
- `install.sh` run twice leaves exactly one `source` line

Tests create their own temp directories and clean up after themselves; none of
them touch the real `config.nu`.
